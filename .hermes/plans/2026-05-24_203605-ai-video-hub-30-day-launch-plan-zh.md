# AI Video Hub - 30天上线与增长执行计划（中文版）

> 给 Hermes：本文件仅用于规划，不执行代码改动。

目标：围绕用户的第一目标——前期先做海外 SEO 引流，后期再通过广告变现——为 AI Video Hub 制定一份 30 天行动计划，避免后续补内容时走偏方向，同时兼顾架构是否需要调整的问题。

架构结论：
- 当前路线是正确的：多页面纯静态 HTML + Vercel 免费部署 + 数据驱动扩内容。
- 现阶段最重要的不是换技术栈，而是先部署、先验证、先收录、先获得真实搜索信号。
- 现阶段继续使用纯静态 HTML 是完全可行的；只有在页面规模继续扩大、维护成本明显上升时，才需要考虑升级到静态生成器。

技术与运营模型：
- 纯静态 HTML / CSS / 轻量 JS
- Vercel 免费部署
- 以后接入 Google Search Console
- 以后接入 GA4
- 前期以内容增长为核心，后期广告为主，赞助位 / 联盟链接为辅

## 二、战略判断

### 结论：现在不要改架构

原因：
1. 当前纯静态 HTML 完全适合 Vercel 免费部署。
2. 当前页面速度快、结构轻、SEO 友好，符合第一阶段目标。
3. 现阶段最大的风险不是“技术架构落后”，而是“网站上线后是否能获得收录和搜索流量”。
4. 现在就迁移到 Astro / Next / 11ty，会增加维护复杂度，但不会直接提升你最需要的结果：流量。

### 当前阶段推荐的架构策略
- 前 30 天继续保持当前静态 HTML 架构不变。
- 只在以下情况出现后，再考虑升级架构：
  - 页面规模超过 100~150 页，维护明显痛苦
  - 后续要大量批量生成页面
  - 后续要稳定做 blog / news / guides
  - 后续模板复用越来越重，手改 HTML 成本太高

### 如果未来要升级架构，推荐顺序
1. 优先考虑静态站点生成器（11ty 或 Astro）
2. 保持静态输出到 Vercel
3. 尽量保留现有 URL 结构

### 现阶段不要因为这些原因改架构
- “框架更新潮流，看起来更先进”
- “以后也许会用到”
- “感觉纯 HTML 不够高级”

对你当前目标来说，简单远比复杂有价值。

## 三、未来 30 天的成功标准

到第 30 天时，这个项目如果算“第一阶段成功”，应该满足：
- 网站已经正常部署在 Vercel
- 域名已经购买并接入，或者至少 Vercel 预览域名已完成完整测试
- sitemap 和 robots 可正常访问
- Google 可以抓取并开始收录核心页面
- 内容更新节奏已经建立，不再是“一次性静态作品”
- 网站已经明显不是简单导流页，而是一个内容型 SEO 站雏形
- 你已经有依据判断这个项目值不值得继续投入

### 第 30 天时建议的判断标准
- 如果已经开始收录，且核心页面开始出现 impressions（展示量），就继续投入
- 如果在基础配置正确的情况下，还是完全没有抓取 / 收录 / 展示，则优先排查原因，而不是盲目扩内容

## 四、30 天行动计划

### 第一阶段：部署与技术验证
### Day 1 - Day 3

目标：先把当前站点上线，并确认基础技术没有问题。

动作：
1. 将 `E:/webTest` 部署到 Vercel 免费版。
2. 上线后逐个检查这些页面：
   - `/`
   - `/index.html`
   - `/categories/video-generation.html`
   - `/tools/sora.html`
   - `/use-cases/ecommerce-ads.html`
   - `/about.html`
   - `/contact.html`
   - `/404.html`
   - `/robots.txt`
   - `/sitemap.xml`
3. 手工抽查首页、分类页、use-case 页、至少 5 个工具页的内链是否正常。
4. 检查移动端展示是否正常。
5. 检查广告位是否依然彻底隐藏，没有空白占位。
6. 确认 Vercel 访问静态页没有路径问题。

后续可能需要改的文件（正式域名后）：
- `index.html`
- `about.html`
- `contact.html`
- `privacy.html`
- `disclaimer.html`
- `categories/*.html`
- `tools/*.html`
- `robots.txt`
- `sitemap.xml`

验证标准：
- 以上路径都能正常打开
- 没有明显死链
- 广告占位不可见
- 手机端没有严重错位

风险：
- 根路径 / 相对路径理解错误
- 浏览器缓存导致误判

---

### 第二阶段：正式域名前的 SEO 准备
### Day 4 - Day 7

目标：即使域名还没买，也先把正式 SEO 切换的动作准备好。

动作：
1. 先想好最终域名方向：
   - 品牌型 `.com`
   - 品牌 + 轻关键词型 `.com`
2. 准备一份域名切换时要统一替换的清单：
   - 全站 canonical
   - OG URL
   - `robots.txt`
   - `sitemap.xml`
   - 联系邮箱（如果后续要用正式邮箱）
3. 提前准备 Search Console 的接入步骤。
4. 提前准备 GA4 接入步骤。
5. 确定正式提交收录时的优先页面顺序：
   - 首页
   - 4 个分类页
   - 10 个重点工具页
   - 4 个 use-case 页面

决策原则：
- 不要因为内容还不“完美”就一直拖着不上线
- 但在域名和 canonical 没替换前，不要急着正式提交 Search Console

验证标准：
- 你已经有一套“域名买完当天就能切换”的操作清单
- 你知道哪些页面是第一批重点收录页面

### 第三阶段：补强内容深度，增强真实 SEO 能力
### Day 8 - Day 14

目标：让网站不只是“有很多页面”，而是真正具备内容厚度。

动作：
1. 先挑 10 个重点工具页继续补内容，例如增加：
   - best for
   - why users search for this tool
   - strengths and limitations
   - alternatives
2. 强化 4 个 use-case 页面，避免它们过薄。
   每页建议补：
   - 更完整的导语
   - 适合谁
   - 选择工具时要比较什么
   - 1 个 FAQ 或 quick comparison note
3. 额外新增至少 2 个更强的 SEO 页面，建议从以下方向选：
   - best ai video tools for agencies
   - best ai video tools for localization
   - best ai video tools for product demo videos
   - sora alternatives
   - heygen alternatives
4. 扩充首页或分类页 FAQ。

内容原则：
- 每个页面都要帮助用户做决策，而不是只让用户点击外链
- 宁可少做一点，但每页更有用，胜过堆很多薄页面

可能改动的文件：
- `tools/*.html`
- `use-cases/*.html`
- 可能新增 `use-cases/` 或 `guides/` 下的新页面
- `sitemap.xml`

验证标准：
- 新页面和旧页面之间有明显差异，而不是模板复读
- 内链是有意义的，不是机械跳转

---

### 第四阶段：内链与留存优化
### Day 15 - Day 21

目标：提升抓取效率、提升用户多看几页的概率，为未来广告变现打基础。

动作：
1. 继续强化工具页内链：
   - 同分类 related tools
   - related use cases
   - 最适合谁 / 下一步看什么
2. 强化分类页内链：
   - category top picks
   - 指向 use-case 页
   - 如果后续新增 compare 页面，也要链过去
3. 每个 use-case 页面都要有“下一步推荐”。
4. 再回头审视首页，减少“用户进来只看一屏就走”的风险：
   - next action 是否足够明显
   - 首页区块层级是否清晰
5. 是否要加本地搜索框，暂时不要急着做；等真实使用后再决定。

原则：
- 对未来广告站来说，用户多看几页非常重要
- 内链不是只为了 SEO，也是为了后期广告展示页数

验证标准：
- 每种页面类型都有自然的下一跳
- 用户不会只能“立刻点外链离开”

---

### 第五阶段：收录验证与阶段复盘
### Day 22 - Day 30

目标：验证这个项目到底有没有生命力，并决定是否继续加码。

在你买域名之后，需要做：
1. 把所有 `example.com` 换成正式域名。
2. 重建并验证 `robots.txt` 和 `sitemap.xml`。
3. 接入 Google Search Console。
4. 提交 sitemap。
5. 如有需要，接入 GA4。
6. 观察这些指标：
   - 页面是否被抓取 / 收录
   - 哪些页面先出现 impressions
   - 哪些页面完全没有信号
   - 哪些页面标题可能需要优化 CTR
7. 找出第一批“有潜力的页面”：
   - 有 impressions 的分类页
   - 有 impressions 的工具页
   - 有 impressions 的 use-case 页
8. 决定下个月的内容重点：
   - 有展示量的页面继续加强
   - 有展示但 CTR 低的页面优化 title / description
   - 长期没信号的页面暂时别盲目重复扩张

第 30 天时的 go / no-go 判断：
- 可以继续投入，如果：
  - 已经开始收录
  - 有页面开始出现 impressions
  - 站内结构稳定
- 先停下来排查，如果：
  - 核心页面没收录
  - sitemap 提交后无反应
  - 内容明显还是偏薄，或页面质量没有达到“内容站”水平

## 五、架构决策标准

### 继续保持纯 HTML 的条件
当满足以下条件时，纯 HTML 仍然适合：
- 页面总量还不算特别夸张
- 更新频率可控
- 站点性能很好
- 手工维护仍然可以接受

### 未来应考虑升级到生成器的条件
- 页面数超过 100~150，手工维护开始痛苦
- 需要大量从统一数据源自动生成页面
- 后续要持续做 news / guides / compare / alternatives
- 相同模板大量复用，人工改一处要改很多页

### 未来如果升级，优先方向
- 11ty 或 Astro
- 仍然保持静态输出
- 仍然部署到 Vercel

### 现阶段明确不建议升级的原因
- 因为“看起来更现代”
- 因为“别人都在用框架”
- 因为“以后也许会有用”

你现在更需要流量验证，而不是技术重构。

## 六、风险与取舍

### 风险 1：薄页面越做越多
问题：后面一旦扩内容，很容易变成“页面变多，但质量没提升”。
应对：
- 每页必须服务一个真实搜索意图
- 初期少而精，比大规模薄内容更重要

### 风险 2：过度建设，迟迟不上线
问题：很容易一直觉得“再补一点就更好了”，导致长期不上线。
应对：
- 当前阶段优先级是部署和验证
- 用真实的搜索信号来决定后续重点，而不是自己空想

### 风险 3：纯 HTML 后期维护压力上升
问题：页面多了以后，重复劳动会越来越明显。
应对：
- 前 30 天先忍受，换来最快上线
- 等规模上来再迁移到静态生成器

### 风险 4：广告心态介入过早
问题：过早恢复广告位，会影响体验和审核。
应对：
- 前期继续隐藏广告位
- 等内容更厚、更像正常站点后再恢复

## 七、推荐的更新节奏

上线后的低摩擦节奏建议：
- 每周 2~3 次内容优化
- 每周 1 次结构检查
- Search Console 接入后，每周 1 次收录 / 展示量复盘

比较好的每周动作组合：
- 强化 1 个分类页
- 强化 3 个工具页
- 新增 1 个 use-case 或 alternatives 页面
- 顺手补强相关内链

## 九、最终建议

未来 30 天，不要重构架构。

你现在最正确的路线是：
1. 先部署
2. 先验证
3. 域名买好后再正式切 canonical / sitemap / robots
4. 再提交收录
5. 根据真实 impressions 和收录反馈去扩内容

这样做，才真正符合你的第一目标：
- 先拿流量
- 再考虑广告变现

如果现在就跳去折腾架构升级，只会增加工作量，不会直接提升最关键的结果。

当前这套“多页面纯静态 HTML + Vercel”架构，足够支撑你完成第一阶段验证。
